Esercizio:
	83/2 = 41 r 1
	41/2 = 20 r 1
	20/2 = 10 r 0
	10/2 = 5 r 0
	5/2 = 2 r 1
	2/2 = 1 r 0

La rappresentazione completa si ottiene componendo la parte intera e quella frazionaria. In virgola fissa, il separatore si trova sempre nello stesso punto rispetto alla sequenza di bit

Abbiamo visto che per i numeri interi non negativi si usa la rappresentazione binaria posizionale. Se si una una rappresentazione a $n$ bit, si possono rappresentare i $2^n$ numeri naturali che sono compresi nell'intervallo: $[0, 2^{n}-1] \cap \mathbb{Z}$

Con 8 cifre binarie (8 bit) si possono rappresentare $2^8$ configurazioni, pari a 256 numeri diversi.

# Numeri negativi
Come possiamo rappresentare i numeri negativi?
## Modulo e segno
La rappresentazione più "naturale"(=intuitiva) è quella con modulo e segno.  
Si rappresenta il segno positivo o negativo del numero con il primo bit della sequenza (quello più a sinistra, il più significativo, MSB): 0 = +; 1 = -.  
Si rappresenta poi il valore assoluto del numero.

Esempio: uso 6 bit
	1 bit di segno
	5 bit destinati al valore assoluto (con padding di zeri a sinistra fino al bit del segno)
	$(101100)_{2MS} = (-12)_{10}$
	$(001100)_{2MS} = (+12)_{10}$

Se si usa una rappresentazione a $n$ bit modulo/segno, posso rappresentare i $2^n -1$ numeri interi nell'intervallo $[-(2^{n-1}-1), 2^{n-1}] \cap \mathbb{Z}$. Per via di questo, ho due rappresentazioni per lo zero (che non ha segno), una che inizia con zero e una con uno.

La rappresentazione modulo/segno, nella pratica, **non si usa**! Per i seguenti problemi
- Si spreca una configurazione con le due rappresentazioni di zero
- Problema grave: l'algoritmo per l'addizione di numeri modulo/segno è complesso (quindi più lento)

Algoritmo per la somma:
```
Se segno(a) = segno(b)
	segno(s) = segno(a), |s| = (|a| + |b|)
altrimenti
	se |a| >= |b|
		segno(s) = segno(a), |s| = (|a| - |b|)
	altrimenti
		segno(s) = segno(b), |s| = (|b| - |a|)
```

## Complemento a due
Una rappresentazione più efficiente è quella denominata complemento a due, definita come:

Dato un numero intero relativo $a \in [-2^{n-1}, 2^{n-1} - 1] \cap \mathbb{Z}$, la rappresentazione in complemento a due con $n$ bit è $\text{C2}_{n} = \text{rapp. bin. di } a \text{ con } n \text{ bit se } a \ge 0; \text{rapp. bin. di } (a+2n) \text{ con } n \text{ bit se } a \lt 0$

Intervallo di rappresentazione dei numeri: $0 \le a \lt 2^n – 2^{n-1}$ per i numeri positivi, $2^n– 2^{n-1} \le b \lt 2^n$ per i numeri negativi. Questi due insiemi non hanno intersezioni.

Proprietà:
- Il segno di un numero rappresentato in complemento a due è ancora il MSB
- La parte restante della rappresentazione NON rappresenta il valore assoluto (lo è **solo** per i numeri non negativi)
- Non ci sono più configurazioni sprecate -> con $n$ bit si rappresentano $2^n$ numeri diversi
- L'addizione dei numeri rappresentati in complemento a due si esegue facendo l'addizione binaria delle rappresentazioni ignorando il riporto in posizione $n$

### Conversione in decimale
La sequenza di n bit $a_{n-1}, a_{n-2} \dots a_{1} a_{0}$ rappresentata in complemento a 2:
- Descrive valori nell'intervallo $[-2^{n-1}, n^{n-1} - 1]$
- Corrisponde al valore intero $-a_{n-1}2^{n-1}+a_{n-2}2^{n-2} + \dots + a_{1}2^{1} + a_{0}2^{0}$

### Somma in complemento a due
Somma con le regole della somma in colonna

```
00000101 +      5 +
00000010        2
----------
00000111        7
```

```
  00000101 +    5 +
  11111110     -2
------------
1|00000011      3
```

Nel secondo esempio ho riporti: li porto avanti e quindi ignoro il bit fuori dall'intervallo di rappresentazione (qui 8 bit, ignoro quindi il nono)

```
01111111 +      127 +
00000001          1
----------
10000000       -128 <-----
```

```
10000000 +     -128 +
11111111         -1
----------
10000000        127 <-----
```

Attenzione: in questi ultimi due casi, vado in overflow! Questi errori si possono verificare, e **non possono essere segnalati** del compilatore.

Si ottiene un overflow quando sommando due numeri con lo stesso segno si ottiene un risultato di segno opposto. Di fatto si ha superamento dei limiti di rappresentazione con i bit a disposizione.

Si osservano le due posizioni più significative: se c'è riporto in una sola delle due, c'è overflow (le posizioni da controllare sono quelle indicate con `v` qui sotto).
```
vv
1111111
--------
01111111 +
00000001
--------
10000000
```
### Importanza del formato
Data una sequenza di bit che rappresentano un numero in binario, per convertirlo in decimale dobbiamo conoscerne il formato.

Complemento a 2 a 8 bit:
- 1111111$_{2}$ = $-2^7+2^6+2^5+2^4+2^3+2^2+2^1+2^0$ = -1$_{10}$
Complemento a 2 a 16 bit:
- 0000000011111111$_{2}$ = $2^7+2^6+2^5+2^4+2^3+2^2+2^1+2^0$ = +255$_{10}$
Modulo e segno a 8 bit:
- 11111111$_{2}$ = $-(2^6+2^5+2^4+2^3+2^2+2^1+2^0)$ = -127$_{10}$

Tutti questi numeri sono otto bit impostati a 1, ma il valore in decimale dipende dal formato!
