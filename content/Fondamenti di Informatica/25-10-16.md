# Variabili
Un programma spesso elabora/manipola **dati**. Dobbiamo quindi poter usare un meccanismo che permetta di memorizzare dati. In Java questo viene chiamato "variabile".

Le variabili Java hanno:
- Nome
- Tipo (l'insieme dei valori ammissibili, e determina l'occupazione di memoria)
- Contenuto
- Attributi (determinano la visibilità, specificano tipi particolari di variabili come static, final)
- Scope (dove posso usare la variabile)

```java
public class Coins1 {
	public static void main(String[] args) {
		int lit = 15000;
		double euro = 2.35;
		
		double totalEuro = euro + lit / 1936.27;
		
		System.out.print("Valore totale in euro ");
		System.out.println(totalEuro);
	}
}
```

Questo programma elabora due tipi di numeri:
- Interi per le lire italiane, che non prevedono l'uso di centesimi/decimi
- Floating point (double) per gli euro, che prevedono decimi e centesimi

Ma perché allora non definisco tutto come double? Ci sono dei buoni motivi:
- Se indico esplicitamente che il numero è intero, so per certo che non esistono decimali per le lire italiane
- I numeri interi sono più efficienti e facili da lavorare in Java

Java infatti è fortemente tipizzato: ogni dato è di un tipo ben preciso già al momento della compilazione del programma. I tipi di dati possono essere primitivi, o riferimenti ad un oggetto. I primi sono int, long, double, char ecc..., i secondi invece contengono un riferimento ad un oggetto come String, Array...

Le variabili possono essere:
- Dichiarate: `int lit`
- Assegnate: `lit = 15000`
- Definite: `int lit = 15000`

La dichiarazione fissa nome, attributo e lo scope. La definizione invece assegna in memoria lo spazio alla variabile. Non posso inoltre dichiarare (o definire) la stessa variabile più volte nello stesso scope.

```java
public class Coins1 {
	public static void main(String[] args) {
		int lit = 15000;
		double euro = 2.35;
		
		double totalEuro = euro + lit / 1936.27;
		
		System.out.print("Valore totale in euro ");
		System.out.println(totalEuro);
	}
	
	private int doubleLit() {
		return lit*2;
	}
}
```
Il programma qui sopra, alla compilazione, restituisce un errore che afferma che il compilatore non riesce a trovare la variabile `lit` nel metodo `doubleLit`.

Ci sono inoltre altri tipi di variabili:
- Statiche: associate alla classe stessa, condivise tra tutte le istanze della classe
- Di istanza: associate ad un oggetto, accessibili a tutta la classe
- Locali: definite in un metodo (o blocco), come nell'esempio qui sopra
- Parametri: variabili presenti nelle firme dei metodi

La scelta dei nomi delle variabili è molto importante: vanno scelti nomi concisi e che descrivano ciò che fa la variabile. In Java inoltre ho altri requisiti:
- Deve essere composta da lettere, numeri o underscore
- Deve iniziare con una lettera, \_, $
- Non può essere una parola riservata (ma la può contenere)
- Non può contenere spazi
- Le lettere maiuscole sono considerate diverse dalle minuscole
- Non può contenere nel nome separatori o operatori

Di solito in Java si usano queste convenzioni:
- Variabili e metodi iniziano con una minuscola
- Classi iniziano con la maiuscola
- I nomi composti (come totalEuro) si scrivono in camelCase (prima lettera minuscola, le iniziali delle parole dopo in maiuscolo)
## Assegnazione
Il valore di una variabile può essere anche modificato.
Sintassi: `nomeVariabile = espressione`. Come in altri linguaggi, uso `=` per assegnare, e non per verificare uguaglianza (quello avviene con `==`).

```java
public class Coins3{
	public static void main(String[] args) {}
		int lit = 15000; // lire italiane
		double euro = 2.35; // euro
		double dollars = 3.05; // dollari
		// calcola il valore totale
		// sommando successivamente i contributi
		double totalEuro = lit / 1936.27;
		totalEuro = totalEuro + euro;
		double convertedDollars = dollars * 0.93;
		totalEuro = totalEuro + convertedDollars;
		System.out.print("Valore totale in euro ");
		System.out.println(totalEuro);
	}
}
```
In questo programma il valore di totalEuro cambia! In entrambi i casi, questa variabile viene incrementata, ovvero aggiungo qualcosa a se stessa.

Le operazioni di scrittura/assegnazione sono distruttive, ovvero sovrascrivo il valore precedente.

## Utilizzo
L'operazione di lettura non è distruttiva. Viene quindi solo letto il valore dalla cella di memoria e non viene modificata.

## Variabili non inizializzate
È buona norma dare sempre un valore di inizializzazione nella dichiarazione di variabili locali (=definirle). Perché? Se non viene inizializzata, non è utilizzabile in lettura.

In altri linguaggi (c/c++) la non inizializzazione può portare a comportamenti imprevedibili dato che viene assegnata della memoria anche se non ancora inizializzato, e questo può portare a letture di valori "spazzatura".

## Scambio di due variabili
Dato che la scrittura è distruttiva, non posso semplicemente fare `a=b;b=a`. Devo usare una variabile temporanea, in cui salvo il valore di `a`, assegno ad `a` il valore di `b`, e infine assegno a `b` il valore di `c`.

# Costanti
Le costanti sono dei valori, simili alle variabili, che però non possono essere modificati. Ad esempio, le costanti vengono usate per valori come costanti fisiche, che non cambiano. Inoltre, se un "magic number" (numero che viene usato nel codice per calcolare un determinato risultato, come tasso di conversione di valuta o altro) viene usato in più punti, posso sostituirlo con una costante, e nel caso ci sia la necessità di modificarlo posso modificare la sola dichiarazione della costante.

Normalmente in Java i nomi delle costanti si scrivono in maiuscolo, con le parole separate da underscore.
# Commenti
I commenti sono delle stringhe che vengono ignorate dal compilatore ma servono a noi per ricordarci o spiegare ciò che fa il codice nelle righe successive.

Iniziano con `//` se alla fine della riga, si aprono e chiudono con `/*` `*/` se utilizzate all'interno della riga o per comprendere più righe.

Sono molto utili nel caso il codice non sia autoesplicativo, sia per se stessi nel caso si ritorni a modificare il codice dopo molto tempo, ma anche se si collabora con altre persone in quanto una cosa che può sembrare ovvia a qualcuno potrebbe non essere compresa da un altro programmatore.

# Literals
I valori costanti per i numeri sono interpretati da Java come int e double, a seconda che abbiano o meno la parte frazionaria. Quindi in alcuni casi devo esplicitare il tipo di numero che voglio assegnargli.

Ad esempio, se ho un numero > Integer.MAX_VALUE e < Long.MAX_VALUE, devo aggiungere una `L` alla fine del numero. `long l = 1345845486748064820L;`

Per i numeri in virgola mobile, devo invece aggiungere `f` alla fine.

Non ci sono solo valori costanti numerici: anche stringhe e caratteri hanno literals. 

# Operatori aritmetici
Divisione: `/`  
Moltiplicazione: `*`  (non può essere sottinteso)
Separatore decimale: `.`  
Resto tra due numeri: `%`.
NON c'è separatore delle migliaia  
I numeri in virgola mobile possono essere espressi in notazione esponenziale

Moltiplicazione e divisione hanno priorità su addizione e sottrazione. È possibile però usare le parentesi per indicare la precedenza di esecuzione che si vuole dare.

L'operatore di frazione è espresso in linea tramite la divisione. Attenzione, visto che la divisione tra due numeri interi darà come risultato il quoziente intero, almeno uno dei due deve essere con virgola per avere un risultato con virgola.

Le operazioni di incremento/decremento sono così comuni in Java che è stato deciso di creare degli operatori appositi: uso `variabile operatore= 5`, ad esempio `totalEuro += dollars`. Non serve quindi riscrivere il nome della variabile.

Esiste inoltre ++ e \--, che incrementano e decrementano i valori di 1 (come scrivere `var += 1`). Possono essere usate prima o dopo del nome della variabile, e questo cambia il loro effetto, ma generalmente si utilizzano dopo il nome (postincremento/postdecremento).

E se voglio usare funzioni più complesse? Esiste la classe `Math`, che contiene metodi statici per funzioni algebriche e trigonometriche:
- `Math.pow(x, y)` restituisce $x^y$
- `Math.sqrt(x)` restituisce $\sqrt{ x }$
- `Math.log(x)` restituisce $\log_{e} x$
- `Math.sin(x)` restituisce $\sin(x)$ in radianti

# Metodi statici
Un metodo statico non viene invocato con un oggetto, ma con un nome di classe
Elabora o modifica inoltre solo i propri parametri espliciti e ciò che dichiara all'interno del metodo stesso.

Esempio di firma: `public static double pow(double a, double b)`
- Public: può essere invocato da qualsiasi classe
- Static: il metodo è statico
- Double: restituirà un double
- Pow: nome del metodo
- `double a, double b`: parametri espliciti e formali del metodo

Quando li utilizzo nel mio codice, posso passargli direttamente valori o anche variabili

# Costanti statiche
Anche le costanti possono essere statiche. Esempio: costante `Math.PI, Math.E`.

# Pacchetti
Tutte la classi della libreria standard sono raccolte in pacchetti. Per usarle, devo importarle: `import nomePacchetto.NomeClasse;`. Le classi Math, System e String sono parte di java.lang, che viene automaticamente importato da Java, quindi non devo importarle a mano.

Posso importare tutte le classi di un pacchetto con `import nomePacchetto.*`, ma è sconsigliato in quanto possono esserci conflitti di nomi con altri pacchetti che importo. Inoltre importerei anche molte altre classi che non uso.

Posso anche usare il nome completo (con pacchetto) della classe quando la uso, ma questo stile di programmazione non si usa in quanto rende più difficile la lettura del codice, aumenta la probabilità di errori di battitura e non c'è effettivo beneficio in non usare gli import.
